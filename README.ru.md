# Mucronix Contact

[🇬🇧 English version](README.md)

Форма обратной связи, встроенная в страницу. Посетитель заполняет её, нажимает «Отправить», и
сообщение уходит владельцу сайта на почту и, если вам это нужно, в чат Telegram. Страница при этом
не перезагружается.

Сделано для **Joomla 6 с выключенным плагином «Поведение - Обратная совместимость 6»**. В этом и
смысл: ни `JFactory`, ни `JText`, ничего из старого мира без пространств имён.

- **Требования:** Joomla 6.0 или новее, PHP 8.3 или новее.
- **Лицензия:** GNU GPL версии 2 или новее, см. `LICENSE`.
- **Поддержка:** support@mucronix.com

---

## Установка

Поставьте ZIP через **Система → Установка → Расширения**, затем опубликуйте модуль в
**Контент → Модули сайта** и задайте ему позицию и назначение пунктам меню, как любому другому
модулю.

Установка не пройдёт на Joomla ниже 6.0 и на PHP ниже 8.3 и скажет, почему. Joomla не читает
минимальные версии из манифеста расширения при первой установке — только с сервера обновлений,
поэтому модуль проверяет их сам.

## Настройки

**Основные** — кому уходит сообщение и что читает посетитель.

| | |
|---|---|
| Получатель | Пусто — берётся e-mail сайта |
| Дополнительные получатели | По одному адресу в строке |
| Тема | Пусто — «Сообщение с сайта *название*» |
| Вводный текст | Показывается над формой, допускается HTML |
| Надпись на кнопке | Пусто — обычная надпись модуля |
| CAPTCHA | Какая CAPTCHA защищает эту форму. «По умолчанию» следует за настройкой сайта |
| Сообщение об успехе | Показывается вместо формы, когда сообщение ушло |
| Страница благодарности | Вместо этого уводит посетителя на вашу собственную страницу |

Своего параметра «заголовок формы» нет намеренно. Joomla уже даёт каждому модулю заголовок со своим
тегом и классом; второй заголовок печатал бы два подряд. Если штатный заголовок модуля скрыт, а
заголовок всё-таки нужен, поместите его в «Вводный текст» — он принимает HTML.

**Страница благодарности** держит пункт меню, а не адрес, поэтому смена алиаса этой страницы не
может молча превратить редирект в 404. Когда она задана, посетитель уходит туда в тот же миг, как
сообщение ушло, и никакого сообщения перед этим не видит — именно это и нужно цели аналитики на той
странице. «Сообщение об успехе» тогда не увидят никогда.

**Поля** — какие поля показаны и какие обязательны, чекбокс согласия и его материал с политикой,
поле вложения со своим списком принимаемых расширений и пределом размера.

**Дополнительные поля** — см. ниже.

**Telegram** — см. ниже.

**Оформление** — подключать ли файл стилей модуля и три места, куда повесить собственные классы
вашего шаблона: вокруг формы, на саму форму и на кнопку отправки.

**Дополнительные параметры** — макет, суффикс класса модуля и **«Вести журнал отправленных»**. Ошибки
уходят в `administrator/logs/mod_mucronix_contact.php` всегда; удачные отправки — только когда это
включено. В обычной работе держите выключенным: такой журнал растёт без предела и записывает, кто и
когда писал.

## Дополнительные поля

Вкладка **«Дополнительные поля»** принимает поля, записанные в формате форм Joomla. Они встают перед
CAPTCHA и попадают в сообщение:

```xml
<field name="phone" type="tel" label="Phone" />
<field name="topic" type="list" label="Topic">
    <option value="sales">Sales</option>
    <option value="support">Support</option>
</field>
```

Принимаемые типы: `text`, `textarea`, `email`, `tel`, `url`, `number`, `list`, `radio`, `checkbox`,
`checkboxes`, `calendar`. Имя должно начинаться с буквы и может содержать только буквы, цифры и
подчёркивания. Имена, которые модуль занял под себя, отклоняются, и так же отклоняется горсть
атрибутов, способных указать полю собственный файл или выбить со страницы одно из полей самого
модуля.

Обо всём пропущенном сказано в уведомлении над формой, с причиной. Это уведомление видят только те,
кто может управлять модулями, — посетитель видит форму как обычно.

Поле `radio` нужно записывать вместе с его вариантами. Ядровый макет переключателя при пустом списке
вариантов не возвращает вообще ничего, и вы получаете подпись, под которой нет элемента управления.

## Telegram

Это та часть, которая чаще всего идёт не так, и почти никогда — в коде.

### 1. Заведите бота

Откройте в Telegram **@BotFather** и отправьте `/newbot`. Он спросит отображаемое имя, затем имя
пользователя, которое должно оканчиваться на `bot`. В ответ он выдаёт токен, выглядящий так:

```
123456789:AAHk4pTaSyZ1qR7vXnB2wLmE5cD8fG0hIjK
```

Потеряли? Он никуда не делся: **@BotFather → /mybots → ваш бот → API Token**. Заводить нового бота
не нужно.

### 2. Про угловые скобки

В инструкциях повсюду адрес Bot API пишут так:

```
https://api.telegram.org/bot<token>/getUpdates
```

`< >` обозначает место, которое надо заполнить. **Частью адреса они не являются.** Если вставить
токен, оставив скобки вокруг него, получится голый `404 Not Found`, и ничего объясняющего к нему не
прилагается. С токеном, приведённым выше, настоящий адрес такой:

```
https://api.telegram.org/bot123456789:AAHk4pTaSyZ1qR7vXnB2wLmE5cD8fG0hIjK/getUpdates
```

Обратите внимание: `bot` остаётся слитно с цифрами. Ни слэша, ни пробела между ними нет.

### 3. Узнайте ID чата

Два способа, годится любой:

- напишите **@userinfobot**, и он сразу ответит вашим собственным id;
- напишите любое сообщение *своему* боту, затем откройте в браузере адрес `getUpdates`, приведённый
  выше, и найдите `"chat":{"id":123456789`.

Если `getUpdates` отвечает `{"ok":true,"result":[]}`, значит боту ещё никто не писал.

### 4. Бот не может написать первым

Telegram не даст боту начать разговор. Пока вы — или кто-то из группы — не отправили боту сообщение,
в доставке отказано, а `getUpdates` остаётся пустым. Симптом ровно такой, каким и звучит: ничего не
приходит, и при этом ничего не выглядит сломанным.

### 5. Группы

Сначала добавьте бота в группу. ID группы **отрицательный** и обычно начинается с `-100`. Минус —
часть числа: его надо вписывать.

### 6. Теперь заполните вкладку

Включите **«Отправлять в Telegram»**, вставьте токен и ID чата. Включите **«Отправлять и вложение»**,
если файлы нужны и в чате тоже, — изображения уходят картинкой, всё остальное файлом, и Telegram
принимает не больше 10 МБ для картинки и 50 МБ для файла.

Письмо уходит первым и чатом не задерживается никогда. Если Telegram откажет или не ответит,
посетитель всё равно увидит, что сообщение прошло, а причина уйдёт в журнал модуля. Поэтому, когда
чат молчит, смотрите журнал.

> ⚠️ **Токен бота лежит в базе данных открытым текстом** и стоит в исходном коде страницы настроек
> модуля для всякого, кто может открыть этот модуль на правку. Свои пароли SMTP и базы данных Joomla
> хранит так же; обратимого шифрования настроек в ядре нет, а шифровать его здесь значило бы
> положить ключ рядом с шифротекстом. Дайте боту доступ только к тому чату, который ему нужен, и
> отзовите токен в @BotFather, если он куда-то утёк.

## Плагин «Кэширование страниц»

Если включён плагин **«Система - Кэширование страниц»**, исключите из кэша страницу с этой формой.
Плагин отдаёт посетителям, которые не вошли на сайт, целиком сохранённые страницы, и тогда ломаются
две разные вещи, и ни одна из них нигде себя не проявляет.

**Токен формы сохраняется вместе со страницей.** Каждому гостю после первого достаётся чужой токен, и
форма отказывается отправлять. Перезагрузка не помогает: она приносит ту же сохранённую страницу с
тем же токеном.

**Страница благодарности подменяет собой форму.** Это хуже и куда менее очевидно. После отправки без
JavaScript модуль перенаправляет обратно на тот же адрес, браузер запрашивает его через GET, и в
хранилище уходит именно эта страница — та, где написано, что сообщение отправлено. Дальше гостям
вместо формы показывают благодарность за чужое сообщение.

Пользуйтесь параметрами **«Исключить пункты меню»** или **«Исключить URL-адреса»** в настройках
плагина.

Сам модуль ничего с этим сделать не может: кэширование отменяется через событие, которое поднимается
задолго до того, как отрисован хоть один модуль, и ответить на него может только плагин. Вместо
этого модуль предупреждает владельца сайта. Если ни один посетитель не может добраться до формы, не
войдя на сайт, ничего из этого к вам не относится — страницы вошедших плагин не трогает.

## Оформление

Модуль поставляется с небольшим файлом стилей, который задаёт отступы между полями, ширину полей,
чекбокс согласия, подсветку ошибок и блок сообщения. Он не рисует ни карточки, ни фона, ни рамки, ни
тени: это дело вашего шаблона, через параметр **«Класс обёртки»**. Для шаблона на Bootstrap подойдёт
`card p-4 shadow-sm`, для YOOtheme — `uk-card uk-card-default uk-box-shadow-medium`.

Цвета и радиус скругления заданы переменными, поэтому одна строка в вашем собственном CSS меняет их
все:

```css
.mcx {
    --mcx-accent: #1f5aa8;
    --mcx-radius: 8px;
}
```

> ⚠️ **Берите для `--mcx-accent` тёмный цвет.** Он красит чекбокс согласия через `accent-color`, а
> тот заливает бокс, поверх которого браузер сам рисует галочку, и она белая — переопределить её
> нельзя. Светлый акцент даёт белое на белом: отмеченный чекбокс выглядит пустым.
>
> На шаблоне, который рисует чекбоксы сам — Bootstrap рисует, Cassiopeia в их числе, через
> `appearance: none`, — эта переменная до чекбокса не доходит вовсе, и его вид остаётся шаблонным.
> Все остальные цвета работают везде.

Выключить файл стилей целиком можно параметром **«Подключать CSS модуля»**, если ваш шаблон
оформляет формы сам.

## Что стоит знать

- **Форма работает без JavaScript.** Она отправляется обычным POST, сервер рисует ошибки в тех же
  местах, где нарисовал бы их скрипт, а ответ приходит через редирект, поэтому обновление страницы
  никогда не спрашивает, отправить ли форму заново.
- **Поле файла браузер никогда не заполняет повторно.** Если в форме понадобится поправить что-то
  ещё, посетителю придётся выбрать файл заново. В описании поля об этом сказано.
- **Одно сообщение в тридцать секунд на сессию.** Вторая форма на том же сайте делит это ожидание с
  первой.
- **Поле вложения печатает тот предел, который действует на самом деле**, а не серверный. Делает оно
  это, неся с собой копию одного ядрового макета, `layouts/mucronix/form/field/file.php`. Отсюда два
  следствия: копию стоит сверять с оригиналом при обновлениях Joomla, и переопределение
  `joomla.form.field.file` из вашего шаблона на это одно поле не действует.
- **В базе данных не хранится ничего.** Ни истории сообщений, ни ящика в панели управления.
