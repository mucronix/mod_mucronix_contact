# Mucronix Contact Lite

[🇬🇧 English version](README.md)

Модуль выводит на странице форму обратной связи. Посетитель заполняет её и нажимает «Отправить» —
сообщение приходит владельцу сайта на почту. Страница при этом не перезагружается.

Модуль рассчитан на **Joomla 6 с выключенным плагином «Поведение - Обратная совместимость 6»**. Ради
этого он и написан: в коде нет ни `JFactory`, ни `JText`, ни других классов без пространств имён.

- **Требования:** Joomla 6.0 или новее, PHP 8.3 или новее.
- **Лицензия:** GNU GPL версии 2 или новее, полный текст — в файле `LICENSE`.
- **Поддержка:** support@mucronix.com

В этом репозитории — **Lite**, бесплатная редакция. В **Pro** есть ещё Telegram, дополнительные
поля, вложения и полный набор параметров оформления:
<https://mucronix.com/products/joomla/mucronix-contact>

## Установка

Скачайте `mod_mucronix_contact-lite-<версия>.zip` со страницы
[Releases](https://github.com/mucronix/mod_mucronix_contact/releases), установите его через
**Система → Установка → Расширения**, затем опубликуйте модуль в разделе **Контент → Модули сайта**:
задайте позицию и назначение пунктам меню, как у любого другого модуля.

На Joomla ниже 6.0 или PHP ниже 8.3 модуль не установится и объяснит причину. Проверку он делает
сам: при первой установке Joomla не смотрит на минимальные версии в манифесте расширения — они
учитываются только при обновлении.

## Настройки

**Модуль** — кому уходит сообщение и что видит посетитель.

| | |
|---|---|
| Получатель | Пусто — адрес сайта |
| Тема | Пусто — «Сообщение с сайта *название сайта*» |
| Вводный текст | Выводится над формой, HTML разрешён |
| Надпись на кнопке | Пусто — обычная надпись |
| CAPTCHA | Какая капча защищает эту форму. «По умолчанию» повторяет настройку сайта |
| Сообщение об успехе | Показывается вместо формы, когда сообщение ушло |

Параметра «заголовок формы» нет намеренно. Joomla и так даёт каждому модулю заголовок со своим тегом
и классом; второй заголовок напечатал бы два подряд. Если заголовок модуля скрыт, а заголовок нужен,
впишите его в «Вводный текст» — он принимает HTML.

**Поля** — какие из полей «Имя», «E-mail» и «Сообщение» показывать и какие обязательны, чекбокс
согласия, материал с политикой конфиденциальности и текст рядом с чекбоксом.

**Оформление** — «Разметка полей», «Собственные стили» и кнопка, открывающая пояснения
по оформлению. См. [Оформление](#оформление).

**Дополнительные параметры** — макет и CSS-класс модуля. Ошибки пишутся
в `administrator/logs/mod_mucronix_contact.php`.

## Плагин «Кэширование страниц»

Если у вас включён плагин **«Система - Кэширование страниц»**, страницу с формой нужно внести в
исключения. Плагин показывает незалогиненным посетителям сохранённые копии страниц, и из-за этого
форма ломается сразу в двух местах — причём незаметно.

**Токен формы попадает в кэш вместе со страницей.** Первый посетитель получает свой, все остальные —
чужой, и отправка у них не проходит. Обновить страницу не поможет: браузер получит ту же копию с тем
же токеном.

**В кэш попадает ответ вместо формы.** Этот случай опаснее, а распознать его ещё труднее. При
отправке без JavaScript модуль перенаправляет браузер на тот же адрес, тот запрашивает страницу
заново через GET — и в кэш уходит уже вариант с сообщением об отправке. Дальше всем гостям вместо
формы показывается подтверждение чужого сообщения.

Страницу исключают параметрами **«Исключить пункты меню»** или **«Исключить URL-адреса»** в
настройках плагина.

Сам модуль исправить это не может: кэширование отменяется событием, которое происходит до вывода
модулей, и ответить на него способен только плагин. Поэтому модуль лишь предупреждает владельца
сайта. Если форма доступна только авторизованным посетителям, проблемы нет — их страницы плагин не
кэширует.

## Оформление

### 1. Два параметра

**«Разметка полей»** добавляет полям классы фреймворка вашего шаблона. Модуль никогда не убирает
классы, поэтому всё, что печатает ядро, остаётся.

| Шаблон | Что выбрать |
|---|---|
| Cassiopeia и другие шаблоны на Bootstrap 5 | Joomla (Bootstrap 5) |
| YOOtheme Pro | UIkit (YOOtheme) |
| Любой другой | попробуйте оба и оставьте лучший — или «Без добавочных классов» |

**«Собственные стили»** определяют, сколько рисует сам модуль: *Полный* — отступы и рамку у каждого
поля; *Базовый* — отступы, строку согласия и подсветку ошибок, не больше; *Нет* — ни одного файла
стилей модуля, форму одевает шаблон.

### 2. Переменные в CSS шаблона

Всё, что рисует модуль, вынесено в переменные. Задайте их в CSS шаблона:

- **Cassiopeia** — файл `user.css`. Пока вы его не создали, его нет: **Система → Шаблоны сайта →
  Редактировать Cassiopeia → Создать файл**, выберите каталог `css`, в поле «Имя файла» впишите
  `user`, в поле «Расширение файла» выберите `css` и нажмите **Создать**. Этот файл Cassiopeia
  подключает сама.
- **YOOtheme Pro** — в кастомизаторе темы, **Настройки → CSS**.

Пишите их на `#mcx-12`, где 12 — номер модуля, или на `body .mcx` сразу для всех форм сайта:

```css
body .mcx {
    --mcx-accent: #1f5aa8;
    --mcx-gap: 10px;
    --mcx-field-radius: 8px;
}
```

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `--mcx-gap` | воздух между соседними полями | `12px` |
| `--mcx-label-gap` | воздух между подписью и её полем | `2px` |
| `--mcx-accent` | поле в фокусе, отмеченный чекбокс | `#2f6fbf` |
| `--mcx-radius` | скругление углов у блоков сообщения и предупреждения | `4px` |
| `--mcx-field-border` | рамка полей | `#dddddd` |
| `--mcx-field-radius` | скругление углов полей | `4px` |
| `--mcx-form-bg` | фон под формой | прозрачный |
| `--mcx-form-max` | максимальная ширина формы | не задана |
| `--mcx-ok`, `--mcx-ok-bg` | блок, который виден после удачной отправки | `#27884a`, `#eaf6ee` |
| `--mcx-error`, `--mcx-error-bg` | отказы и поля, к которым они относятся | `#c0392b`, `#fdecea` |
| `--mcx-notice`, `--mcx-notice-bg` | предупреждение, видное только управляющим модулями | `#b8860b`, `#fff8e5` |

`--mcx-field-border`, `--mcx-field-radius`, `--mcx-form-bg` и `--mcx-form-max` действуют только при
«Собственных стилях» = «Полный»: их читает файл стилей, который «Базовый» и «Нет» не подключают.

> ⚠️ **Для `--mcx-accent` берите тёмный цвет.** Переменная задаёт цвет чекбокса согласия, а галочку
> поверх браузер рисует белой. При светлом акценте получится белое на белом, и отмеченный чекбокс
> будет выглядеть пустым.

То же самое, с примерами, написано на странице, которую открывает кнопка **«Открыть пояснения по
оформлению»**. Страница идёт вместе с модулем, по одной на язык:
`media/mod_mucronix_contact/docs/styling.<язык>.html`.

### 3. Переопределение макета

Скопируйте `tmpl/default.php` в `templates/<ваш шаблон>/html/mod_mucronix_contact/default.php` и
правьте копию — или поручите это Joomla: **Система → Шаблоны сайта → ваш шаблон → Создание
переопределений → Модули → mod_mucronix_contact**. Joomla найдёт копию сама, а обновления её не
тронут. Файл `default_mail.php` рядом — тело письма, которое приходит вам.

> ⚠️ **Этот макет — не только разметка.** В нём лежит обвязка, на которой держится отправка, и
> большинство поломок здесь проходят тихо: форма выглядит правильно, просто сообщения перестают
> приходить.

Уберёте что-то отсюда — **отправка перестанет проходить**:

- скрытое поле `mcx_module_id`: по нему модуль узнаёт, из какого его экземпляра пришло сообщение;
- скрытое поле `mcx_page` — адрес страницы, с которой отправлено;
- токен, который печатает `HTMLHelper::_('form.token')`;
- сам цикл вывода полей: их имена собираются с номером модуля, и набранные руками `input` на эти
  имена не отзовутся.

Уберёте что-то отсюда — **AJAX-слой отвалится беззвучно**: форма уйдёт обычной отправкой, работать
будет, и никто не заметит:

- класс `mcx` на внешнем блоке;
- класс `mcx-form` у `<form>`;
- сам `<form>` внутри этого внешнего блока — обработчик слушает именно там;
- две строки, которые регистрируют и подключают скрипт;
- строки `Text::script(...)`, без них кнопка и сообщение об ошибке заговорят по-английски.

Уберёте что-то отсюда — **сообщения окажутся не на месте или нигде**:

- блок `mcx-message`, куда пишется всё, что происходит после отправки;
- `mcx-submit` у кнопки — этим она показывает, что отправляет;
- `mcx-field--<имя>` у каждого поля: так ошибка находит своё поле;
- `mcx-field-wrap` вокруг поля — туда эта ошибка и кладётся;
- `id="mcx-<номер модуля>"` на внешнем блоке: якорь, куда возвращает отправка без JavaScript;
- скрытое поле-ловушка: его потеря нигде не видна и стоит всей защиты.

## Что стоит знать

- **Форма работает без JavaScript.** Она отправляется обычным POST, ошибки выводит сервер — в тех же
  местах, что и скрипт, — а результат приходит через редирект, поэтому обновление страницы не
  предлагает отправить форму ещё раз.
- **Одно сообщение в тридцать секунд на сессию.** Ограничение общее для сайта: вторая форма ждёт
  столько же.
- **Сообщения нигде не сохраняются.** Ни истории в базе данных, ни ящика в панели управления.

## Обновления

У модуля есть сервер обновлений, поэтому новые версии Lite Joomla предлагает штатно. Релизы и
описания к ним — на <https://github.com/mucronix/mod_mucronix_contact/releases>, а что менялось
в каждой версии — в [CHANGELOG.md](CHANGELOG.md).

Обновление до Pro редакции Lite не предлагается никогда: редакции обновляются с разных адресов.

> ⚠️ **Установка Lite поверх Pro стоит тех настроек, которые есть только в Pro.** Установщик об этом
> предупреждает и продолжает. Формы работают дальше — с тем, что есть в Lite; настройки Pro хранятся
> до первого сохранения модуля и в этот момент пропадают. Чтобы вернуться, установите Pro снова, не
> сохраняя модули.
