# Mucronix Contact

[🇬🇧 English version](README.md)

Модуль выводит на странице форму обратной связи. Посетитель заполняет её и нажимает «Отправить» —
сообщение приходит владельцу сайта на почту. Страница при этом не перезагружается.

Модуль есть в Joomla! Extensions Directory: [Mucronix Contact Lite](https://extensions.joomla.org/extension/contacts-and-feedback/contact-forms/mucronix-contact-lite/) · [Mucronix Contact Pro](https://extensions.joomla.org/extension/contacts-and-feedback/contact-forms/mucronix-contact-pro/)

Модуль рассчитан на **Joomla 6 с выключенным плагином «Поведение - Обратная совместимость 6»**. Ради
этого он и написан: в коде нет ни `JFactory`, ни `JText`, ни других классов без пространств имён.

- **Требования:** Joomla 6.0 или новее, PHP 8.3 или новее.
- **Лицензия:** GNU GPL версии 2 или новее, полный текст — в файле `LICENSE`.
- **Поддержка:** support@mucronix.com

В этом репозитории — **Lite**, бесплатная редакция. В **Pro** есть ещё Telegram, дополнительные
поля, вложения и полный набор параметров оформления:
<https://mucronix.com/products/joomla/mucronix-contact-pro>

## Установка

Скачайте `mod_mucronix_contact-lite-<версия>.zip` со страницы
[Releases](https://github.com/mucronix/mod_mucronix_contact/releases), установите его через
**Система → Установка → Расширения**, затем опубликуйте модуль в разделе **Контент → Модули сайта**:
задайте позицию и пункты меню, как для любого другого модуля.

На Joomla ниже 6.0 или PHP ниже 8.3 модуль не установится и сообщит причину. Эту проверку модуль
делает сам: при первой установке Joomla не смотрит на минимальные версии, указанные в манифесте
расширения, — только при обновлении.

## Настройки

**Модуль** — кому уходит сообщение и что видит посетитель.

| | |
|---|---|
| Получатель | Если пусто — адрес почты сайта |
| Тема | Если пусто — «Сообщение с сайта *название сайта*» |
| Вводный текст | Выводится над формой, можно использовать HTML |
| Надпись на кнопке | Если пусто — стандартная надпись |
| CAPTCHA | Капча для этой формы. «По умолчанию» — как в общих настройках сайта |
| Сообщение об успехе | Показывается вместо формы после успешной отправки |

Параметра «заголовок формы» нет намеренно: у каждого модуля Joomla уже есть свой заголовок,
с выбором тега и класса, и второй заголовок дал бы два подряд. Если заголовок модуля скрыт,
а заголовок над формой нужен, впишите его в «Вводный текст» — там можно использовать HTML.

**Поля** — какие из полей «Имя», «E-mail» и «Сообщение» показывать и какие из них обязательны,
чекбокс согласия, материал с политикой конфиденциальности и текст рядом с чекбоксом.

**Оформление** — «Разметка полей», «Собственные стили» и кнопка, которая открывает пояснения
по оформлению. См. [Оформление](#оформление).

**Дополнительные параметры** — макет и CSS-класс модуля. Ошибки модуль записывает в файл
`administrator/logs/mod_mucronix_contact.php`.

## Плагин «Кэширование страниц»

Если включён плагин **«Система - Кэширование страниц»**, добавьте страницу с формой в исключения.
Плагин показывает гостям (посетителям, которые не вошли на сайт) сохранённые копии страниц, и форма
от этого ломается двумя способами — оба незаметно.

**Токен формы сохраняется в кэше вместе со страницей.** Свой токен получает только первый
посетитель, остальные — чужой, и сообщение у них не отправляется. Обновление страницы не помогает:
приходит та же копия с тем же токеном.

**В кэш попадает страница с ответом вместо формы.** Это опаснее, и заметить это ещё труднее. При
отправке без JavaScript модуль перенаправляет браузер на тот же адрес, браузер загружает страницу
заново (GET), и в кэш попадает уже страница с сообщением об отправке. После этого все гости вместо
формы видят подтверждение чужого сообщения.

Исключить страницу можно в настройках плагина — параметрами **«Исключить пункты меню»** или
**«Исключить URL-адреса»**.

Сам модуль это исправить не может: отключить кэширование можно только до того, как Joomla начнёт
выводить модули, и сделать это способен только плагин. Поэтому модуль лишь предупреждает владельца
сайта. Если форма видна только вошедшим пользователям, проблемы нет: для них плагин страницы
не кэширует.

## Оформление

### 1. Два параметра

**«Разметка полей»** добавляет полям классы CSS-фреймворка вашего шаблона. Модуль классы только
добавляет и никогда не убирает: всё, что выводит ядро Joomla, остаётся на месте.

| Шаблон | Что выбрать |
|---|---|
| Cassiopeia и другие шаблоны на Bootstrap 5 | Joomla (Bootstrap 5) |
| YOOtheme Pro | UIkit (YOOtheme) |
| Любой другой | попробуйте оба и оставьте лучший — или «Без добавочных классов» |

**«Собственные стили»** определяют, сколько оформления добавляет сам модуль: *Полный* — отступы
и рамка у каждого поля; *Базовый* — только отступы, строка согласия и подсветка ошибок; *Нет* —
модуль не подключает своих стилей, форму оформляет шаблон.

### 2. Переменные в CSS шаблона

Всё оформление модуля задаётся CSS-переменными. Их можно переопределить в CSS шаблона:

- **Cassiopeia** — файл `user.css`. По умолчанию его нет, его нужно создать: **Система → Шаблоны
  сайта → Редактировать Cassiopeia → Создать файл**, выберите каталог `css`, в поле «Имя файла»
  впишите `user`, в поле «Расширение файла» выберите `css` и нажмите **Создать**. Этот файл
  Cassiopeia подключает сама.
- **YOOtheme Pro** — в кастомизаторе темы, **Настройки → CSS**.

Для одной формы пишите селектор `#mcx-12`, где 12 — ID модуля; для всех форм сайта сразу —
`body .mcx`:

```css
body .mcx {
    --mcx-accent: #1f5aa8;
    --mcx-gap: 10px;
    --mcx-field-radius: 8px;
}
```

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `--mcx-gap` | расстояние между полями | `12px` |
| `--mcx-label-gap` | расстояние между подписью и полем | `2px` |
| `--mcx-accent` | цвет рамки поля в фокусе и отмеченного чекбокса | `#2f6fbf` |
| `--mcx-radius` | скругление углов у блоков сообщения и предупреждения | `4px` |
| `--mcx-field-border` | цвет рамки полей | `#dddddd` |
| `--mcx-field-radius` | скругление углов полей | `4px` |
| `--mcx-form-bg` | фон под формой | прозрачный |
| `--mcx-form-max` | максимальная ширина формы | не задана |
| `--mcx-ok`, `--mcx-ok-bg` | блок с сообщением об успешной отправке | `#27884a`, `#eaf6ee` |
| `--mcx-error`, `--mcx-error-bg` | сообщения об ошибках и поля с ошибкой | `#c0392b`, `#fdecea` |
| `--mcx-notice`, `--mcx-notice-bg` | предупреждение, которое видят только те, кто управляет модулями | `#b8860b`, `#fff8e5` |

`--mcx-field-border`, `--mcx-field-radius`, `--mcx-form-bg` и `--mcx-form-max` работают только при
«Собственных стилях» = «Полный»: их использует файл стилей, который в режимах «Базовый» и «Нет»
не подключается.

> ⚠️ **Для `--mcx-accent` берите тёмный цвет.** Переменная задаёт цвет чекбокса согласия, а галочку
> поверх браузер рисует белой. При светлом акценте получится белое на белом, и отмеченный чекбокс
> будет выглядеть пустым.

То же самое с примерами — на странице, которая открывается кнопкой **«Открыть пояснения по
оформлению»**. Страница входит в пакет модуля, отдельно для каждого языка:
`media/mod_mucronix_contact/docs/styling.<язык>.html`.

### 3. Переопределение макета

Скопируйте `tmpl/default.php` в `templates/<ваш шаблон>/html/mod_mucronix_contact/default.php` и
правьте копию. Или пусть копию сделает Joomla: **Система → Шаблоны сайта → ваш шаблон → Создание
переопределений → Модули → mod_mucronix_contact**. Joomla сама будет использовать копию, а
обновления модуля её не затронут. Файл `default_mail.php` рядом — это шаблон письма, которое
приходит вам.

> ⚠️ **Этот макет — не только разметка.** В нём есть служебные элементы, без которых отправка
> не работает. Большинство поломок здесь незаметны: форма выглядит как обычно, но сообщения
> перестают приходить.

Если удалить что-то из этого списка, **сообщения перестанут отправляться**:

- скрытое поле `mcx_module_id`: по нему модуль определяет, из какой формы пришло сообщение;
- скрытое поле `mcx_page` — адрес страницы, с которой отправлено сообщение;
- токен, который выводит `HTMLHelper::_('form.token')`;
- сам цикл вывода полей: имена полей содержат ID модуля, и поля `input`, написанные вручную,
  с ними не совпадут.

Если удалить что-то из этого списка, **AJAX-отправка незаметно перестанет работать**: форма будет
отправляться обычным способом, с перезагрузкой страницы, и никто этого не заметит:

- класс `mcx` на внешнем блоке;
- класс `mcx-form` у `<form>`;
- тег `<form>` должен оставаться внутри этого внешнего блока: скрипт отслеживает отправку
  именно там;
- две строки, которые регистрируют и подключают скрипт;
- строки `Text::script(...)`: без них надпись на кнопке и сообщение об ошибке будут на английском.

Если удалить что-то из этого списка, **сообщения появятся не там или не появятся вовсе**:

- блок `mcx-message`: в него выводится результат отправки;
- класс `mcx-submit` у кнопки: по нему кнопка показывает, что идёт отправка;
- класс `mcx-field--<имя>` у каждого поля: по нему ошибка привязывается к своему полю;
- блок `mcx-field-wrap` вокруг поля: в него выводится текст ошибки;
- `id="mcx-<ID модуля>"` на внешнем блоке: к этому месту страница прокручивается после отправки
  без JavaScript;
- скрытое поле-ловушка для ботов: если его удалить, внешне ничего не изменится, но эта защита
  от спама перестанет работать.

## Что стоит знать

- **Форма работает и без JavaScript.** Тогда она отправляется обычным способом, ошибки показываются
  в тех же местах, а после отправки страница загружается заново через перенаправление — поэтому
  при обновлении страницы браузер не предлагает отправить форму ещё раз.
- **Одно сообщение в 30 секунд на сессию.** Ограничение действует на весь сайт: после отправки
  из одной формы другая тоже будет ждать 30 секунд.
- **Сообщения нигде не сохраняются.** Модуль не хранит их ни в базе данных, ни в панели управления.

## Обновления

У модуля есть сервер обновлений, поэтому о новых версиях Lite Joomla сообщит сама, как об
обновлениях других расширений. Релизы и описания к ним — на
<https://github.com/mucronix/mod_mucronix_contact/releases>, а что менялось в каждой версии —
в [CHANGELOG.md](CHANGELOG.md).

Lite никогда не предложит обновиться до Pro: редакции получают обновления с разных серверов.

> ⚠️ **Если поставить Lite поверх Pro, настройки, которые есть только в Pro, пропадут.** Установщик
> предупредит об этом, но установку не остановит. Формы продолжат работать с возможностями Lite.
> Настройки Pro остаются в базе, пока модуль не сохранят: при первом сохранении они удаляются.
> Чтобы их вернуть, установите Pro снова, не сохраняя модули перед этим.
