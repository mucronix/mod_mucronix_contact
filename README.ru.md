# Mucronix Contact

[🇬🇧 English version](README.md)

Модуль выводит на странице форму обратной связи. Посетитель заполняет её и нажимает «Отправить» —
сообщение приходит владельцу сайта на почту, а при желании ещё и в Telegram. Страница при этом не
перезагружается.

Модуль рассчитан на **Joomla 6 с выключенным плагином «Поведение - Обратная совместимость 6»**. Ради
этого он и написан: в коде нет ни `JFactory`, ни `JText`, ни других классов без пространств имён.

- **Требования:** Joomla 6.0 или новее, PHP 8.3 или новее.
- **Лицензия:** GNU GPL версии 2 или новее, полный текст — в файле `LICENSE`.
- **Поддержка:** support@mucronix.com

---

## Установка

Установите ZIP через **Система → Установка → Расширения**, затем опубликуйте модуль в разделе
**Контент → Модули сайта**: задайте позицию и назначение пунктам меню, как у любого другого модуля.

На Joomla ниже 6.0 или PHP ниже 8.3 модуль не установится и объяснит причину. Проверку он делает
сам: при первой установке Joomla не смотрит на минимальные версии в манифесте расширения — они
учитываются только при обновлении.

## Настройки

**Основные** — кому уходит сообщение и что видит посетитель.

| | |
|---|---|
| Получатель | Если не заполнено, берётся e-mail сайта |
| Дополнительные получатели | По одному адресу в строке |
| Тема | Если не заполнено — «Сообщение с сайта *название*» |
| Вводный текст | Выводится над формой, допускается HTML |
| Надпись на кнопке | Если не заполнено, используется стандартная |
| CAPTCHA | Какая CAPTCHA защищает форму. «По умолчанию» — выбранная в настройках сайта |
| Сообщение об успехе | Выводится вместо формы после отправки |
| Страница благодарности | Посетитель попадает на выбранную страницу |

Отдельного параметра для заголовка формы нет, и это сделано намеренно: у каждого модуля Joomla уже
есть собственный заголовок с выбором тега и класса, а второй дал бы на странице два заголовка
подряд. Если штатный заголовок скрыт, а подпись над формой нужна, добавьте её во «Вводный текст» —
там разрешён HTML.

В параметре **«Страница благодарности»** хранится идентификатор пункта меню, а не адрес, поэтому
смена алиаса страницы не превратит переход в 404. Когда страница выбрана, посетитель попадает на неё
сразу после отправки, без промежуточного сообщения — это и нужно, чтобы на ней сработала цель
аналитики. «Сообщение об успехе» в этом случае не показывается вообще.

**Поля** — какие поля выводятся и какие из них обязательны, чекбокс согласия со ссылкой на материал
с политикой, поле вложения со списком допустимых расширений и пределом размера.

**Дополнительные поля** — о них ниже.

**Telegram** — о нём ниже.

**Оформление** — подключать ли стили модуля и куда добавить собственные классы шаблона: на блок
вокруг формы, на саму форму и на кнопку отправки.

**Дополнительные параметры** — макет, суффикс класса модуля и **«Вести журнал отправленных»**.
Ошибки записываются в `administrator/logs/mod_mucronix_contact.php` всегда, удачные отправки —
только если включить этот параметр. В обычной работе его лучше держать выключенным: журнал растёт
без ограничений и хранит сведения о том, кто и когда писал.

## Дополнительные поля

На вкладке **«Дополнительные поля»** описываются поля в формате форм Joomla. Они выводятся перед
CAPTCHA и попадают в сообщение:

```xml
<field name="phone" type="tel" label="Phone" />
<field name="topic" type="list" label="Topic">
    <option value="sales">Sales</option>
    <option value="support">Support</option>
</field>
```

Допустимые типы: `text`, `textarea`, `email`, `tel`, `url`, `number`, `list`, `radio`, `checkbox`,
`checkboxes`, `calendar`. Имя поля начинается с буквы и состоит из букв, цифр и подчёркиваний.
Имена, занятые самим модулем, не принимаются; отклоняются и атрибуты, которыми можно подменить макет
поля или убрать со страницы одно из полей модуля.

Обо всём, что отклонено, модуль сообщает над формой и объясняет причину. Это сообщение видят только
те, кто может управлять модулями, — посетителю форма выводится как обычно.

У поля `radio` обязательно перечисляйте варианты. Без них макет ядра не выведет ничего, и на
странице останется подпись без самого переключателя.

## Telegram

Здесь чаще всего и возникают проблемы — почти всегда из-за настройки, а не из-за кода.

### 1. Заведите бота

Отправьте боту **@BotFather** команду `/newbot`. Он спросит название бота, затем имя пользователя —
оно должно заканчиваться на `bot`. В ответ придёт токен:

```
123456789:AAHk4pTaSyZ1qR7vXnB2wLmE5cD8fG0hIjK
```

Если токен потерялся, заводить нового бота не нужно: он всегда есть в **@BotFather → /mybots → ваш
бот → API Token**.

### 2. Про угловые скобки

В инструкциях адрес Bot API обычно пишут так:

```
https://api.telegram.org/bot<token>/getUpdates
```

Угловые скобки обозначают место для подстановки и **частью адреса не являются**. Если вставить токен
вместе с ними, Telegram ответит `404 Not Found` без каких-либо пояснений. С токеном из примера выше
правильный адрес выглядит так:

```
https://api.telegram.org/bot123456789:AAHk4pTaSyZ1qR7vXnB2wLmE5cD8fG0hIjK/getUpdates
```

Обратите внимание: `bot` пишется слитно с цифрами токена, без слэша и пробела.

### 3. Узнайте ID чата

Подойдёт любой из двух способов:

- напишите боту **@userinfobot** — он сразу пришлёт ваш id;
- отправьте любое сообщение своему боту и откройте в браузере адрес `getUpdates` — нужное число
  будет в `"chat":{"id":123456789`.

Ответ `{"ok":true,"result":[]}` означает, что боту ещё никто не писал.

### 4. Бот не может написать первым

Telegram запрещает боту начинать переписку. Пока вы или кто-то из участников группы не напишете
боту, сообщения доставляться не будут, а `getUpdates` будет отвечать пустым списком. Уведомления при
этом просто не приходят, и никакой ошибки нигде не появляется.

### 5. Группы

Сначала добавьте бота в группу. ID группы **отрицательный** и обычно начинается с `-100`. Минус —
часть числа, его тоже нужно вписать.

### 6. Заполните вкладку

Включите **«Отправлять в Telegram»**, укажите токен и ID чата. Параметр **«Отправлять и вложение»**
добавит в чат файл из формы: изображения уходят картинкой, остальное — документом. Telegram
принимает до 10 МБ для картинки и до 50 МБ для файла.

Письмо отправляется первым и от Telegram не зависит. Если чат не ответит или вернёт ошибку,
посетитель всё равно увидит подтверждение, а причина запишется в журнал модуля. Поэтому, если
сообщения в чат не приходят, начинайте с журнала.

> ⚠️ **Токен бота хранится в базе данных в открытом виде** и виден в исходном коде страницы настроек
> всем, кто может редактировать модуль. Так же Joomla хранит пароли SMTP и базы данных: обратимого
> шифрования настроек в ядре нет, а шифровать своими силами бессмысленно — ключ пришлось бы положить
> рядом с шифротекстом. Дайте боту доступ только к нужному чату, а если токен утёк, отзовите его в
> @BotFather.

## Плагин «Кэширование страниц»

Если у вас включён плагин **«Система - Кэширование страниц»**, страницу с формой нужно внести в
исключения. Плагин показывает незалогиненным посетителям сохранённые копии страниц, и из-за этого
форма ломается сразу в двух местах — причём незаметно.

**Токен формы попадает в кэш вместе со страницей.** Первый посетитель получает свой, все остальные —
чужой, и отправка у них не проходит. Обновить страницу не поможет: браузер получит ту же копию с тем
же токеном.

**В кэш попадает страница благодарности.** Этот случай опаснее, а распознать его ещё труднее. При
отправке без JavaScript модуль перенаправляет браузер на тот же адрес, тот запрашивает страницу
заново через GET — и в кэш уходит уже вариант с сообщением об отправке. Дальше всем гостям вместо
формы показывается благодарность за чужое сообщение.

Страницу исключают параметрами **«Исключить пункты меню»** или **«Исключить URL-адреса»** в
настройках плагина.

Сам модуль исправить это не может: кэширование отменяется событием, которое происходит до вывода
модулей, и ответить на него способен только плагин. Поэтому модуль лишь предупреждает владельца
сайта. Если форма доступна только авторизованным посетителям, проблемы нет — их страницы плагин не
кэширует.

## Оформление

Модуль подключает небольшой файл стилей — он задаёт отступы между полями, ширину полей, вид чекбокса
согласия, подсветку ошибок и блок сообщения. Карточку, фон, рамку и тень он не задаёт — это остаётся
за шаблоном, для чего есть параметр **«Класс обёртки»**. Для Bootstrap подойдёт `card p-4
shadow-sm`, для YOOtheme — `uk-card uk-card-default uk-box-shadow-medium`.

Цвета и радиус скругления вынесены в переменные, поэтому переопределить их можно одной строкой в
стилях шаблона:

```css
.mcx {
    --mcx-accent: #1f5aa8;
    --mcx-radius: 8px;
}
```

> ⚠️ **Для `--mcx-accent` берите тёмный цвет.** Переменная задаёт цвет чекбокса согласия через
> `accent-color`: браузер заливает им сам чекбокс, а галочку поверх рисует белой, и повлиять на неё
> нельзя. При светлом акценте получится белое на белом, и отмеченный чекбокс будет выглядеть пустым.
>
> Шаблоны, которые оформляют чекбоксы самостоятельно через `appearance: none` — так делают Bootstrap
> и Cassiopeia, — эту переменную игнорируют, и внешний вид там задаёт шаблон. Остальные цвета
> работают везде.

Если шаблон оформляет формы сам, стили модуля можно не подключать: за это отвечает параметр
**«Подключать CSS модуля»**.

## Что стоит знать

- **Форма работает без JavaScript.** Она отправляется обычным POST, ошибки выводит сервер — в тех же
  местах, что и скрипт, — а результат приходит через редирект, поэтому обновление страницы не
  предлагает отправить форму ещё раз.
- **Браузер не заполняет поле файла повторно.** Если после отказа в форме нужно что-то исправить,
  файл придётся выбрать заново. Об этом сказано в описании поля.
- **Одно сообщение в тридцать секунд на сессию.** Ограничение общее для сайта: вторая форма ждёт
  столько же.
- **Рядом с полем вложения показан настоящий предел размера**, а не серверный. Ради этого модуль
  везёт с собой копию макета ядра — `layouts/mucronix/form/field/file.php`. Отсюда два следствия:
  копию нужно сверять с оригиналом при обновлении Joomla, а переопределение `joomla.form.field.file`
  из шаблона на это поле не действует.
- **Сообщения нигде не сохраняются.** Ни истории в базе данных, ни ящика в панели управления.
