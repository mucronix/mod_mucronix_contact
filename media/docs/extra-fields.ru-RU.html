Пояснения к дополнительным полям

Вкладка Дополнительные поля — единственное место модуля, где разметку пишут руками. Ниже — готовый пример на каждый тип поля, набор для типовой формы и всё, что модуль отклоняет, с причинами.

Как это устроено

  • Поля описываются в поле Описание полей, в формате форм Joomla: по одному элементу <field> на поле. Оборачивать их в <form> или <fieldset> не нужно — просто пишите поля одно за другим.
  • На странице они встают после полей модуля, перед CAPTCHA, в том порядке, в каком описаны. В письмо и в Telegram попадают так же, по порядку.
  • У каждого поля три обязательные вещи: имя name, тип type и подпись label. Имя пишется латиницей и посетителю не видно, подпись — на языке сайта.
  • required="true" делает поле обязательным.
  • Сохранив модуль, откройте страницу с формой, не выходя из админки. Если что-то отклонено, над формой появится сообщение с причиной. Его видят только те, кто может управлять модулями; посетителю форма выводится как обычно. Что значит каждое сообщение — в пункте 6.

Что проверяет сервер, а что только браузер. Атрибуты pattern, maxlength, min и max сами по себе работают лишь в браузере: это подсказка посетителю, а не защита. Проверку на сервере включает атрибут validate — он есть в примерах ниже там, где нужен.

1. Одиннадцать типов

Каждый пример можно вставить как есть. Подпись и варианты замените своими, имя — по желанию.

text — строка

<field name="company" type="text" label="Компания" maxlength="100" />

textarea — несколько строк

<field name="address" type="textarea" label="Адрес доставки" rows="3" />

email — ещё один адрес

<field name="email_extra" type="email" label="Запасной e-mail" validate="email" />

Без validate="email" адрес проверит только браузер. Основное поле «E-mail» у модуля своё, заводить его здесь не нужно.

tel — телефон

<field name="phone" type="tel" label="Телефон" inputmode="tel" validate="tel" />

validate="tel" принимает от 7 до 15 цифр; плюс, пробелы, точки, дефисы и скобки между ними допускаются. inputmode="tel" открывает на телефоне цифровую клавиатуру: само поле Joomla выводит обычной строкой.

url — адрес сайта

<field name="website" type="url" label="Ваш сайт" hint="https://" validate="url" />

Адрес принимается только вместе с https:// или http://: просто example.com будет отклонён, поэтому подсказка в поле не лишняя.

number — число

<field name="guests" type="number" label="Сколько гостей" min="1" max="20" step="1" validate="number" />

С validate="number" границы min и max соблюдает и сервер.

list — выпадающий список

<field name="topic" type="list" label="Тема обращения" validate="options">
    <option value="">— выберите —</option>
    <option value="question">Вопрос</option>
    <option value="order">Заказ</option>
    <option value="other">Другое</option>
</field>

В письмо приходит текст варианта («Заказ»), а не его значение (order). Первая строка с пустым значением нужна, чтобы обязательный список нельзя было отправить невыбранным.

radio — один вариант из нескольких

<field name="reply_by" type="radio" label="Как вам ответить" default="mail" validate="options">
    <option value="mail">Письмом</option>
    <option value="call">Звонком</option>
</field>

Варианты обязательны: без них на странице останется подпись без самого переключателя.

checkbox — одна галочка

<field name="callback" type="checkbox" label="Перезвоните мне" value="1" />

В письмо приходит «Да» или «Нет». Обязательная галочка в письмо не выводится вовсе: без неё форма не отправится, значит, ответ всегда один и тот же.

checkboxes — несколько галочек

<field name="interests" type="checkboxes" label="Что вас интересует">
    <option value="price">Цены</option>
    <option value="terms">Сроки</option>
    <option value="demo">Показ</option>
</field>

В письмо приходят подписи отмеченных вариантов через запятую.

calendar — дата

<field name="visit_date" type="calendar" label="Удобная дата" />

Дата приходит в виде 2026-10-15.

2. Готовый набор для типовой формы

Телефон, тема обращения, удобное время и согласие на рассылку. Вставляется целиком и работает сразу.

<field name="phone" type="tel" label="Телефон" hint="+380 44 123-45-67"
    pattern="[0-9+\(\) \-]{7,20}" inputmode="tel" validate="tel" required="true" />

<field name="topic" type="list" label="Тема обращения" required="true" validate="options">
    <option value="">— выберите —</option>
    <option value="question">Вопрос</option>
    <option value="order">Заказ</option>
    <option value="other">Другое</option>
</field>

<field name="call_time" type="radio" label="Когда вам удобно говорить" default="any" validate="options">
    <option value="any">В любое время</option>
    <option value="morning">До обеда</option>
    <option value="evening">После обеда</option>
</field>

<field name="newsletter" type="checkbox" label="Присылайте мне новости" value="1" />
  • pattern у телефона не даёт отправить буквы прямо в браузере, не дожидаясь ответа сервера. Скобки и дефис внутри квадратных скобок написаны с обратной чертой намеренно: без неё браузер молча отбрасывает весь шаблон и пропускает что угодно.
  • Согласие на рассылку — необязательная галочка, отдельная от согласия на обработку данных. В письме будет «Да» или «Нет»: вы видите, кто согласился. Сделав её обязательной, вы заставите соглашаться всех и перестанете видеть ответ в письме.
  • Согласие на обработку данных сюда не добавляйте: оно у модуля своё, параметр Чекбокс согласия на вкладке «Поля».

Как проверить: отправьте форму без телефона и без темы — оба поля должны подсветиться, каждое со своим сообщением. Затем заполните и отправьте: в письме тема приходит словом «Заказ», а не order.

3. Занятые имена

Восемь имён принадлежат самому модулю, и поле с таким именем пропускается:

name, email, message, attachment, consent, captcha, mcx_hp, mcx_module_id.

Регистр не важен: Email и CAPTCHA заняты точно так же.

Причина: Joomla, встретив второе поле с тем же именем, не добавляет его, а ставит на место первого — и ни о чём не сообщает. Хуже всего это с captcha: на месте проверки оказалось бы обычное текстовое поле, которое устраивает любое значение, а форма продолжала бы считать себя защищённой. С mcx_hp то же самое происходит с ловушкой для роботов.

Нужен второй адрес или второе сообщение — назовите поле иначе: email_extra, details. Нужен файл — включите Поле вложения на вкладке «Поля».

Два дополнительных поля с одним именем тоже не уживаются: остаётся первое.

4. Атрибуты, которые модуль снимает

Поле при этом остаётся и работает, пропадает только атрибут — и над формой появляется сообщение о том, какой именно.

  • id — идентификатор Joomla строит из имени сама. Заданный руками, он обходит список занятых имён: поле с любым именем и id="mcx_hp" вытесняет ловушку для роботов со страницы, и защита пропадает без единого признака.
  • layout, layoutIncludePath — подменяют файл, который рисует поле, файлом, названным в настройке.
  • fieldset, formsource — уводят поле в другое место страницы или подгружают постороннее описание формы.
  • addfieldprefix, addformprefix, addruleprefix, addfilterprefix, addfieldpath, addformpath, addrulepath, addfilterpath — решают, какой именно код стоит за словом в type. С ними список разрешённых типов теряет смысл целиком: в описании по-прежнему написано text, а работает уже чужой класс — причём для всех форм, которые строятся на странице после этой.

Для обычной формы ни один из этих атрибутов не нужен.

5. Каким может быть имя

Первая — латинская буква, дальше латинские буквы, цифры и подчёркивание: ^[a-zA-Z][a-zA-Z0-9_]*$.

Годятся phone, call_time, phone2. Не годятся call-time, call.time, 2phone, телефон.

Дефис и точка запрещены не из строгости. Идентификатор поля на странице Joomla получает из имени, заменяя всё, кроме букв, цифр и подчёркивания, на подчёркивание. Поля call-time, call.time и call_time получили бы один и тот же идентификатор, и на странице осталось бы одно из трёх — молча.

6. Как читать предупреждения

Все они выводятся над формой и начинаются словами «Дополнительные поля». Отправке формы они не мешают: пропущенное поле просто не выводится, остальные работают.

Дополнительные поля: описание не удалось разобрать, поэтому ни одно поле не добавлено.
Ошибка в самой записи: незакрытый тег, потерянная кавычка, пропущенная косая черта в конце />. Дальше в сообщении названы строка и причина — чинить надо именно эту строку. Пока она не исправлена, не добавляется ни одно поле, даже верно описанные.
Дополнительные поля: в описании нет ни одного элемента field, поэтому ничего не добавлено.
Запись читается, но полей в ней нет. Обычно это опечатка в слове field или текст, оставшийся вместо описания.
Дополнительные поля: поле без имени пропущено.
Допишите полю name.
Дополнительные поля: имя … отклонено, поле пропущено.
В имени есть что-то, кроме латинских букв, цифр и подчёркивания, или оно начинается не с буквы. См. пункт 5.
Дополнительные поля: имя … занято модулем, поле пропущено.
Имя из списка в пункте 3. Назовите поле иначе.
Дополнительные поля: имя … встречается несколько раз, оставлено только первое поле.
Два поля с одним именем. Переименуйте второе.
Дополнительные поля: у поля … нет типа, оно пропущено.
Допишите полю type — один из одиннадцати из пункта 1.
Дополнительные поля: поле … пропущено, тип … здесь не принимается.
Тип не из одиннадцати. Проверьте написание — checkboxes, а не checkbox-list, — и загляните в пункт 7: возможно, этот тип не принимается намеренно.
Дополнительные поля: у поля … удалён атрибут ….
Поле работает, снят только названный атрибут. Уберите его из описания, и сообщение исчезнет. См. пункт 4.

Те же причины, одной строкой и по-английски, попадают в журнал administrator/logs/mod_mucronix_contact.php — при каждой отправке формы, пока описание не исправлено.

7. Чего здесь не будет никогда

У Joomla типов полей гораздо больше одиннадцати. Эти семь не принимаются намеренно:

  • sql — выполняет запрос, записанный в его атрибуте, и показывает ответ базы данных на странице. Право править модуль превратилось бы в право читать таблицы.
  • user — выносит на открытую страницу выбор пользователя из админки.
  • file — открывает вторую загрузку файлов в обход проверок первой. Для файла есть Поле вложения.
  • subform — строит поля внутри поля; проверки имён, типов и атрибутов до них не дотягиваются.
  • editor — тянет на открытую страницу редактор из админки со всеми его кнопками.
  • accessiblemedia — то же самое с выбором изображений из медиа-менеджера.
  • hidden — кладёт в сообщение значение, которого посетитель не вводил и не видел.

Телефон, список, дата, галочки — всё, что нужно форме обратной связи, одиннадцатью типами закрывается. Если не хватает именно поля из этого списка, нужен конструктор форм, а не этот модуль.
