Пояснения по оформлению

Два параметра на вкладке Оформление решают, какую часть вида модуль рисует сам. Всё остальное делается из шаблона, двумя способами: несколькими переменными CSS, которые читает форма, и переопределением её макета.

1. Два параметра

  • «Разметка полей» — Joomla (Bootstrap 5) для Cassiopeia и других шаблонов на Bootstrap, UIkit (YOOtheme) для YOOtheme Pro, Без добавочных классов оставляет поля ровно такими, какими их рисует шаблон.
  • «Собственные стили» — Полный рисует рамку у каждого поля и расставляет поля; Базовый только расставляет их и показывает ошибки; Нет отдаёт форму шаблону целиком.

Поменяв любой из них, обновите страницу с Ctrl+Shift+R: иначе в браузере остаётся прежний файл стилей.

2. Куда писать правила и ваш селектор

Правила ниже пишутся в CSS вашего шаблона, а не в модуль.

  • Cassiopeia — файл user.css. Пока вы его не создали, его нет: Система → Шаблоны сайта → Редактировать Cassiopeia → Создать файл, выберите каталог css, в поле «Имя файла» впишите user, в поле «Расширение файла» выберите css и нажмите Создать. Этот файл Cassiopeia подключает сама.
  • YOOtheme Pro — в кастомизаторе темы, Настройки → CSS.

Каждый пример начинается со слова ВАША-ФОРМА. Замените его на #mcx-12, где 12 — номер этого модуля: столбец ID в списке модулей сайта. Чтобы правило действовало на все формы обратной связи сразу, напишите вместо этого body .mcx.

3. Переменные, которые работают при «Полном» и «Базовом»

ВАША-ФОРМА {
    --mcx-gap: 16px;
    --mcx-label-gap: 4px;
}
  • --mcx-gap — расстояние между полями, по умолчанию 12px.
  • --mcx-label-gap — расстояние между подписью и её полем, 2px.

У сообщений над формой и под полями свои цвета:

ВАША-ФОРМА {
    --mcx-error: #b00020;
    --mcx-error-bg: #fdeaec;
    --mcx-ok: #1f7a3d;
    --mcx-ok-bg: #e9f6ed;
    --mcx-radius: 6px;
}
  • --mcx-error, --mcx-error-bg — ошибка: её текст и рамка поля, к которому она относится, и фон блока сообщения.
  • --mcx-ok, --mcx-ok-bg — сообщение после успешной отправки.
  • --mcx-radius — скругление углов блока сообщения, 4px.

4. Переменные, которые работают только при «Полном»

ВАША-ФОРМА {
    --mcx-field-border: #b8bec7;
    --mcx-field-radius: 8px;
    --mcx-form-max: 560px;
    --mcx-accent: #0a7d55;
}
  • --mcx-field-border — цвет рамок полей, #dddddd.
  • --mcx-field-radius — скругление их углов, 4px.
  • --mcx-form-max — максимальная ширина формы. Без неё форма занимает всю ширину своей колонки.
  • --mcx-accent — цвет поля в фокусе и отмеченного чекбокса, #2f6fbf. Выбирайте тёмный: белая галочка на светлом цвете не видна. При Базовом переменная доходит только до чекбокса согласия, и лишь в шаблоне, который оставляет рисование чекбоксов браузеру.

Фону под формой нужен ещё и отступ внутри, поэтому они пишутся вместе:

ВАША-ФОРМА {
    --mcx-form-bg: #f6f7f9;
    padding: 16px 20px;
}

При Базовом и Нет переменные этого раздела ничего не делают, кроме одного случая, названного выше: файл стилей, который их читает, подключает только Полный.

5. Переопределение макета

Когда переменной мало, можно заменить саму разметку — так, как Joomla позволяет это для любого модуля: Система → Шаблоны сайта → ваш шаблон → Создание переопределений → Модули → mod_mucronix_contact. Joomla скопирует два файла в templates/ваш-шаблон/html/mod_mucronix_contact/, и с этого момента сайт берёт копии:

  • default.php — форма на странице;
  • default_mail.php — тело письма, которое приходит вам.

Чтобы оставить исходный вид и добавить рядом второй, сохраните копию под другим именем, например compact.php, и выберите её в модуле: Дополнительные параметры → Макет.

Что переопределение default.php обязано сохранить, иначе форма перестанет отправляться: обёртку с классом mcx и идентификатором mcx-…, форму с классом mcx-form, блок mcx-message, кнопку mcx-submit, блок mcx-hp с атрибутом hidden, два скрытых поля mcx_module_id и mcx_page и токен формы. После обновления модуля сравните свою копию с новым исходным файлом.

Если правило ничего не делает

  • Проверьте, что ВАША-ФОРМА заменена — с решёткой # и верным номером.
  • Обновите страницу с Ctrl+Shift+R и очистите кэш шаблона, если он у него свой.
  • Проверьте «Собственные стили»: при Нет ни один файл стилей модуля не подключается и ни одна переменная не читается.
