Styling notes

Two settings on the Appearance tab decide how much of the look the module draws. Everything else is done from your template, in two ways: a few CSS variables the form reads, and a layout you can override.

1. The two settings

  • Field Markup — Joomla (Bootstrap 5) for Cassiopeia and other Bootstrap templates, UIkit (YOOtheme) for YOOtheme Pro, No Added Classes to leave the fields exactly as the template draws them.
  • Own Styles — Full draws a border round every field and spaces the fields out; Basic only spaces them out and shows errors; None hands the whole form to the template.

After changing either, reload the page with Ctrl+Shift+R: the browser keeps the previous stylesheet otherwise.

2. Where the rules go, and your selector

The rules below go into the CSS of your template, not into the module.

  • Cassiopeia — the file user.css. It does not exist until you create it: System → Site Templates → Cassiopeia Details and Files → New File, choose the folder css, give the name user and the file type css, then press Create. Cassiopeia loads that file by itself.
  • YOOtheme Pro — in the customizer, Settings → CSS.

Every example begins with YOUR-FORM. Replace it with #mcx-12, where 12 is the id of this module: the ID column in the list of site modules. To reach every contact form on the site at once, write body .mcx instead.

3. Variables that work with Full and Basic

YOUR-FORM {
    --mcx-gap: 16px;
    --mcx-label-gap: 4px;
}
  • --mcx-gap — the space between one field and the next, 12px by default.
  • --mcx-label-gap — the space between a label and its field, 2px.

The messages above the form and under the fields have colours of their own:

YOUR-FORM {
    --mcx-error: #b00020;
    --mcx-error-bg: #fdeaec;
    --mcx-ok: #1f7a3d;
    --mcx-ok-bg: #e9f6ed;
    --mcx-radius: 6px;
}
  • --mcx-error, --mcx-error-bg — an error: its text and the border of the field it belongs to, and the background of the message block.
  • --mcx-ok, --mcx-ok-bg — the message shown after sending.
  • --mcx-radius — the corner radius of the message block, 4px.

4. Variables that work with Full only

YOUR-FORM {
    --mcx-field-border: #b8bec7;
    --mcx-field-radius: 8px;
    --mcx-form-max: 560px;
    --mcx-accent: #0a7d55;
}
  • --mcx-field-border — the colour of the field borders, #dddddd.
  • --mcx-field-radius — the rounding of their corners, 4px.
  • --mcx-form-max — the maximum width of the form. Without it the form takes the whole width of its column.
  • --mcx-accent — the colour of a field in focus and of a ticked checkbox, #2f6fbf. Choose a dark one: a white tick does not show on a light colour. With Basic it reaches the consent checkbox alone, and only on a template that leaves the drawing of checkboxes to the browser.

A background behind the form needs room inside it as well, so the two are written together:

YOUR-FORM {
    --mcx-form-bg: #f6f7f9;
    padding: 16px 20px;
}

With Basic and None the variables of this section do nothing, the one case named above aside: the stylesheet that reads them is loaded only with Full.

5. Overriding the layout

When a variable is not enough, the markup itself can be replaced, the way Joomla does it for any module: System → Site Templates → your template → Create Overrides → Modules → mod_mucronix_contact. Joomla copies two files into templates/your-template/html/mod_mucronix_contact/, and from then on the site uses the copies:

  • default.php — the form on the page;
  • default_mail.php — the body of the message you receive.

To keep the original and add a second look beside it, save the copy under another name, for example compact.php, and choose it in the module, Advanced → Layout.

What an override of default.php has to keep, or the form stops sending: the wrapper with the class mcx and the id mcx-…, the form with the class mcx-form, the block mcx-message, the button mcx-submit, the block mcx-hp with its hidden attribute, the two hidden inputs mcx_module_id and mcx_page, and the form token. After an update of the module, compare your copy with the new original.

When a rule does nothing

  • Check that YOUR-FORM was replaced — with the # and the right id.
  • Reload with Ctrl+Shift+R, and clear the cache of the template if it has one.
  • Check Own Styles: with None no stylesheet of the module is loaded, and no variable is read.
